# PetClinic recording fixtures

The prototype imports these files directly with Vite `?raw`. The Java audit compiles the same files; no separate mock implementation is used for the audit.

## Baseline

Reference: the local `spring-petclinic-sdd` checkout at `3b59d3a27f16aa9551e6ef34b5486e4335540f77`, using Spring Boot 4.0.3. The canonical upstream is https://github.com/spring-projects/spring-petclinic.

The demo assumes an earlier booking extension, represented by `baseline/`:

- `Visit` already has a `LocalTime` and a selected `Vet`. Standard upstream PetClinic has neither. A saved appointment is called confirmed; there is no invented `status` field or confirmation endpoint.
- The existing form has hourly choices from 09:00 through 18:00. This makes the 18:00 case possible; the previous prototype's 09:00–16:00 picker contradicted it.
- `VetFormatter` already binds the vet ID. It lives in the owner package with the form binding, and uses the real `VetRepository.findAll()` API. It is not newly generated by this task.
- Visits are saved through `OwnerRepository.save(owner)` and the existing Owner → Pet → Visit cascade. No invented `VisitRepository`, `Visit.pet` back-reference, or `VetRepository.findById()` is required.
- Required vet/time/date checks apply on form submission. Historical date-only visits remain valid persisted records. `description` retains `@NotBlank`.
- The form's model contains owner, pet, vets and time slots on both GET and invalid POST. Entity IDs are not bindable. A visit is added to the pet only after validation succeeds.
- H2 retains the real specialties and vet_specialties tables, uses supported identity syntax and explicit column lists for existing visit seeds.

## Working-hours change

`generated/` adds weekday schedules and half-open `[start, end)` validation in `processNewVisitForm()`. A missing schedule rejects new bookings. `DayOfWeek` persists by enum name. Java time-window validation and SQL constraints agree. Schema/data files are H2 development initialization, not a production data migration; no statement cancels or updates existing visits.

Feedback narrows the rule to new bookings. The controller's scope is reviewed and made explicit; the preservation regression is added. Completed schema/entity/repository/seed work is retained.

## Real verification

Run `node scripts/verify-petclinic-demo.mjs /path/to/spring-petclinic` from the prototype. Set `MAVEN_BIN` if Maven is not on PATH, and `MAVEN_OFFLINE=1` to use an existing local Maven cache. The script copies the supplied checkout into a temporary directory, applies baseline then generated files, and runs `VisitControllerTests`. The original Java checkout is never modified.

Eight integration tests passed against the reference checkout on September 7, 2026. They exercise Spring MVC binding, Thymeleaf rendering, real JPA repositories and H2 persistence. Tests cover valid/invalid submission, schedule boundaries, missing schedules, and preservation after shortening the schedule. The preservation test creates an 18:00 appointment under a 19:00 closing time, persists it, changes closing time to 17:00, saves another valid visit through the owner cascade, reloads the confirmed appointment, checks its ID/date/time/vet/description, and rejects a new 18:00 booking without adding a record. Test dates use the next Monday instead of a stale fixed date.

This is a focused audit of the displayed change on the demo baseline, not a claim that the complete upstream test suite or other database profiles support the booking extension.
